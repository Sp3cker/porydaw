# Controller amendments to the plan (2026-09-24)

Written after the P0 gate. The plan's audit-derived populations were
miscalibrated by an audit script that only counted `public`-modified members
and that missed the macro's second registration path. This file is the
authoritative delta; `spec.md` R1-R3 and `.omp/rules/qtbridge-surface.md` were
rewritten to match, and the amended dispatch lists supersede the
corresponding brief sections.

## Ground truth re-derived from the pinned macro

`QtBridgeableMacro.processVariableDeclaration` (`QtBridgeableMacro.swift:247-274`):

```swift
guard variableDecl.isValidForRegistration else { return }   // !private && !computed && !didSet && instance
if variableDecl.hasAttribute("@QtIgnored") { return }
guard variableDecl.isSupportedGettableType
        || variableDecl.hasAttribute("@QtTracked") else { return }
builder.registerProperty(name:keyPath:)
```

Consequences:

1. `@QtTracked` **with an inferred type registers** — 233 such members are
   live, QML-visible properties today. The plan's "add the missing type
   annotation to ~197 members" edit (brief 04 shape 2) is therefore churn
   with a meta-type delta, and is cancelled.
2. `private(set)` counts as `private` for `isValidForRegistration`
   (`isPrivate` matches the `private` token, `Extensions.swift:35-39`), so
   setter-restricted members never register and need no `@QtIgnored`.
3. `@QtIgnored` on `private`/`private(set)`/`static` members is a strict
   no-op (registered early-return); on a non-private computed member it is
   inert but documents intent and stays.

## Guard corrections dispatched (P0b)

1. B1 must report only the two invisibility classes plus the two hygiene
   classes above; `@QtTracked` + inferred type is conforming and is not
   reported at all. `@QtIgnored` on non-private computed members is not
   reported.
2. B2 must recognize property-NOTIFY handlers (`on<Name>Changed` where the
   target class has a registered property of that name) as satisfied, and
   must not attribute a handler to a class it cannot prove from the
   `Connections` target expression — unresolved targets stay silent.
3. Baseline stays controller-generated; `--update-baseline` stays
   deterministic and shrink-only.

## Revised gate criteria (supersede plan.md success criteria 2)

- After the P1 waves: `verify:bridge` reports zero `UNANNOTATED_MEMBER`,
  `UNTRACKED_CUSTOM_TYPE`, `REDUNDANT_TRACKED`, `REDUNDANT_IGNORED`,
  `SUGAR_OPTIONAL_RETURN`, `UNREACHABLE_QML`.
- B2's residual population after brief 05 must be empty of the signals it
  deletes; any remaining `SIGNAL_NEVER_OBSERVED`/`HANDLER_NEVER_EMITTED`
  entries are reported to the human with evidence rather than deleted.
- The baseline file is regenerated by the controller at each wave and is
  expected to reach zero entries for the five B1 classes and `UNREACHABLE_QML`.
