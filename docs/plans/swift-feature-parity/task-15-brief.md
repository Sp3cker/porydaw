# Context

BANK-CLOSE: the user-authorized close policy — ordinary Save stays current-song/current-bound-bank, switching `-G` neither autosaves nor prompts, and existing project/window Save–Discard–Cancel handling must account for every dirty bank, including banks no longer bound to any open song. Today the close machinery is tab-oriented only: `SongTabsController.settleCloseAll` (src/swift/app/SongTabsController.swift:480) walks `tabs` alone; `ApplicationSession.startProjectSwitch` bypasses the walk entirely when `songTabs.tabCount == 0` (src/swift/app/ApplicationSession.swift:880) and `ShellPresenter.beginClose` calls `finishClose()` directly on the same condition (src/swift/app/shell/ShellPresenter.swift:312). A dirty bank whose last bound tab closed (Discard detaches the session but reverts nothing) or whose tab switched `-G` away stays cached in `ProjectService.bankViews` (src/swift/app/SharedBankState.swift:60) and in the voicegroup store's records; `ProjectService.close()` (src/swift/app/ProjectService.swift:640) then destroys it silently. The C++ close prompt had a bank-dirty label variant with no Swift counterpart (recorded in the stale comment at src/ui/songview/quick/swiftroll/SongTabs.qml:50). Read [plan.md](plan.md) Global constraints and [handoff.md](handoff.md) "Authorized subsequent bank-close policy". The handoff's read-only leads are adjudicated here: both `tabCount == 0` bypasses are removed; the walk's transactional expectations are preserved unchanged (window-close cancel already retains earlier tab removals, and the bank stage runs only after the strip empties); the dialog gets an explicit bank close-target model instead of a magic tab id; discard-during-save and stale completion reuse the existing revision/publication identity authorities.

# Interface contract

- Preserve the tab gate exactly: `requestClose`, `confirmSave`, `confirmDiscard`, `cancelClose` and `closeAfterSave(tabId:saved:)` keep their current tab semantics, `pendingCloseId` remains a real tab id or -1, and the `startCloseAll`/`startProjectSwitchCloseAll` → `closeAllResolved(closed:)` protocol with its `allTabsClosed`/`closeCancelled` signals is unchanged.
- Add an explicit bank close-target model on `SongTabsController`, not a magic tab id: a QML-visible `public var pendingCloseBankTitle: String = ""` (empty = no bank target) plus an internal pending target carrying the bank's `BankBindingIdentity` and `NativeBankLease`, supplied by the application. The three gate answers dispatch on which target kind is pending. `requestClose`, `requestReload` and `requestReplacement` additionally refuse while a bank target is pending, exactly as they refuse on `pendingCloseId != -1` today.
- The bank stage runs in `settleCloseAll` after the tab loop empties and before `isClosingAll = false` / `closeAllResolved(closed: true)`: enumerate the service's dirty banks minus this walk's already-answered identities, present the first and return; exhausted → resolve. The answered-identity set resets when a walk starts. Save marks the identity answered only on success (a refused save leaves the gate up to re-answer); Discard marks it answered and advances; Cancel aborts through the existing `closeAllResolved(closed: false)` path.
- `ApplicationSession.startProjectSwitch` drops the `tabCount == 0` shortcut: every switch installs `pendingProjectSwitch` and calls `startProjectSwitchCloseAll()`; with no tabs and no dirty banks the walk settles through to `finishProjectSwitch` unchanged, and Cancel still closes the candidate service and emits `closeCancelled`.
- `ApplicationSession` supplies the enumeration synchronously on the main actor from `catalogService` (a nil service yields none) and gains `saveBankBeforeClose(_ target:)` mirroring `saveTabBeforeClose` (src/swift/app/ApplicationSession.swift:700): `saveInProgress` guard, `lastSaveError`/`operationFailed` on failure, completion reported back through a controller method `bankCloseAfterSave(saved:)`.
- `ShellPresenter.beginClose` routes every close through `session.requestCloseAll()` under `closePending`; the direct `finishClose()` branch for `tabCount == 0` is removed. `allTabsClosed` → `finishClose` is unchanged, so a clean empty shell settles through the same walk.
- `ProjectService` gains `public func saveBank(lease: NativeBankLease) async throws -> AppliedBankEdit`: the existing bank stage of `save(_:bank:)` — owner guard against `store.publicationOwner`, `store.saveVoicegroup(lease:)`, `appliedBank` clean receipt, `publish(from:)` — with no MIDI/flags stages. `ProjectBankViews` gains an internal dirty enumeration (e.g. `dirtyBanks() -> [AppliedBankEdit]`) ordered by sourcePath then sectionLabel; `reset(owner:)` is unchanged.
- Discard-during-save and stale completion keep identity authority where it already lives: a bank Save blocks that target's Discard and Cancel while in flight, and its completion resolves only the still-pending target; published receipts still pass through `SharedBankState.accept`, whose `publicationRevision` guard already refuses an older clean receipt against a newer dirty edit (src/swift/app/SharedBankState.swift:44). Tab saves keep `SongDocument.captureSave`/`didSave` revision+identity authority unchanged (src/swift/core/SongDocument.swift:389, 408).
- `SongTabs.qml` projects the bank target explicitly: the `songTabCloseDialog` (line 345) is visible for either target kind, its label binds the pending bank target's title — the bank's `loadName`, e.g. "fixture_rich" — when one is pending, restoring the C++ bank-dirty label intent recorded in the stale comment at lines 50–54, which is rewritten where it becomes false; the strip's `enabled` gating (line 159) covers the bank target. No new dialog, buttons or controls.

# Task-specific constraints

No autosave or prompt on `-G` switching; no all-bank Save command (ordinary Save stays current-song/current-bound-bank, and the gate's Save answers one target at a time); no new dialog, buttons or placeholder controls; no bank-edit revert or cache-eviction API (Discard means proceed without saving — the record dies with the outgoing service or the host exit); no rollback of earlier tab removals when a window close is cancelled mid-walk (existing transactional semantics, inspected and deliberate); no change to single-tab close/reload semantics; no magic tab ids, timestamp games or proof-count targets; keep the public save/edit contracts and the task-12/14 interfaces intact. A tab answered Discard whose bank edits then orphan is asked about once more by name at the bank stage: that second prompt is the honest cost of the authorized every-dirty-bank accounting and must not be suppressed by guessing the earlier answer covered the bank.
