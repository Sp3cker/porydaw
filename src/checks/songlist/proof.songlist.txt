Migration notes
- songLabels() widened with this slice: pd_service_list_songs now lists
  every playable song (isPlayable == hasMid), where the committed op
  filtered registered && hasMid. songLabels() therefore returns
  unregistered strays too. The old dialog consumer
  (ApplicationSession.replaceProject -> labels, the song-open picker)
  now sees strays — intentional: the native panel's playable gate listed
  them, and opening a stray is legitimate. Consumers needing
  registered-only must filter SongListing.registered from songs().
- Register/Delete are service operations, not presenter intents:
  pd_service_song_registration_plan/_register/_deletion_plan/_delete
  (B012/B013). The presenter still emits request* intents for the shell's
  menu/dialog tier; the transaction itself lives behind the C ABI.
