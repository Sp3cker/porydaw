Status and evidence
This is an assertion-site inventory, not a count-based equivalence claim. Every
original macro/failure site in tst_transport.cpp appears below, including the
init preconditions and the ringingTail control guards. loadedSong carries no
assertion site: it returns an empty pointer on encoding/write/load/publication
failure and each per-case proof inventories the caller's QVERIFY2 of that
return value. Constructors, cleanup, engine() and runTransportCheck carry no
sites. S identifiers identify exact Swift predicates, listed after the
inventory. MATCHED identifies equivalent model predicates; execution must still
be verified. PARTIAL identifies related Swift predicates with an explicit
unproved condition. NATIVE identifies retained native-device/harness
obligations; it does not establish coverage of any converted check. GAP
identifies an original predicate without a replacement assertion.

Execution ownership
runTransportCheck executes the TransportTest slots under the transportcheck
lane on a fresh forced-null AudioEngine per slot. The paired Swift side runs
under swiftcore: runAudioControllerChecks calls checkAuditionTailTransitions
(tails.swift), which carries the PARTIAL predicates for the ringingTail
control guards. transportfixture.swift builds the Swift timelines and carries
no report.expect calls (verified by search), so no shared-helper predicate
section applies to it.

Fixture, sequence and row constraints
Every slot binds PORYDAW_AUDIO_BACKEND=null and fails (never skips) when the
forced-null init or backend report breaks. ringingTail strikes
previewNoteTimed(track, 60, 127, 0.15 * sampleRate), requires audibility
within a 2 s qWaitFor bound, waits a further 400 ms wall-clock, then requires
the slow release still to ring. No data rows expand these sites: one guard
execution per helper call (tails.cpp calls it from playFromStoppedCutsAuditionTail
and spacePathSeekAndPlayCutsTail).
Original setup, branch guards and helper implementations at the reference
revision remain authoritative; this inventory does not replace those sources.

  std::shared_ptr<const PdPlaybackData> TransportTest::loadedSong(const TransportMidiFile &midi,
                                                                  const char *what)
  {
      const QByteArray bytes = midi.encode();
      if (bytes.isEmpty()) {
          qWarning("%s: fixture MIDI encoding failed", what);
          return {};
      }

      QTemporaryFile file;
      if (!file.open() || file.write(bytes) != bytes.size() || !file.flush()) {
          qWarning("%s: could not write fixture MIDI bytes", what);
          return {};
      }

      PdPlaybackData *publication = nullptr;
      std::array<char, 1024> diagnostic{};
      const QByteArray path = QFile::encodeName(file.fileName());
      if (!pd_playback_data_load_file(path.constData(), engine().sampleRate(), &publication,
                                      diagnostic.data(), diagnostic.size())) {
          if (publication)
              pd_playback_data_release(publication);
          qWarning("%s: Swift playback loader failed: %s", what, diagnostic.data());
          return {};
      }
      if (!publication) {
          qWarning("%s: Swift playback loader returned no publication", what);
          return {};
      }
      return std::shared_ptr<const PdPlaybackData>{publication, pd_playback_data_release};
  }
