This is an assertion-site inventory, not a count-based equivalence claim. Every
original macro/failure site in this file appears below. The file exercises
layout::initialize/fontPx/fontPxF/space/singlePixel against closed-form
expectations at a lane-supplied base font size. Source context preserves setup,
data rows, loops, and guards between assertions verbatim.
MATCHED means a corresponding Swift predicate was identified and would execute;
PARTIAL means a related Swift predicate exists with a stated unproved condition;
GAP means no equivalent Swift assertion is established;

presenter-level Swift check cannot establish. Pure scale tables (A006-A009)
execute in TypographyLayoutChecks.swift via runTypographyLayoutChecks; the
process-scoped initialization guards (A001-A005) have no Swift counterpart
because Swift layout is a pure value of the lane base, not process-global state.

Fixture, sequence and row constraints
The first five entries run once per lane inside initializationIsProcessScoped; the
initialize-twice guard (A003-A004) requires process-scoped initialization: the
second initialize with the same size must succeed without touching the
stylesheet, while size 0 and size+1 must fail. A006-A009 are the four switch
branches of layoutScale, expanded over the layoutScale_data rows: 8 fontPx
rows, 3 fontPxF rows, 8 space-token rows, and 1 single-pixel row (20 rows per
lane, 60 executions across the three lanes). expectedIntegral clamps through
qMax(1, ...) with a 0.0 short-circuit; the scale-operation switch returns
immediately after each branch assertion. Swift rows: the same 8 fontPx
multipliers, 3 fontPxF multipliers, 8 space multipliers and the single-pixel
case execute as pinned literal tables at bases 12, 16 and 18
(TypographyLayoutChecks.swift:15-48).
Original setup, branch guards, and helper implementations at the reference
revision remain authoritative; this inventory does not replace those sources.
